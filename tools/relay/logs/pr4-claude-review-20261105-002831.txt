## NITS

1. **Revert can be killed mid-run if SSH drops** (`step-11-e810-capture.sh:273`, `:312-313`). `ssh -t` sends SIGHUP and `tee` dies. The `echo`s in `cleanup` and in the child `step11-revert.sh` then take SIGPIPE, so the rollback aborts at its first echo. Suggested fix: add `trap '' HUP PIPE` after line 273, or run the apply under `systemd-run`. The KVM fallback covers this, but it is exactly the case AJ worries about.
2. **`install_tuning` failures bypass the auto-revert** (`:745`, trap at `:312`). The script has `set -e` but no `set -E`, so the ERR trap does not fire inside functions. An unguarded failure in `install_tuning` (`mkdir`, `install`, `daemon-reload`, the final `sha256sum`) exits with `failed=0`. There is then no `REVERTING` and no `CONFIG-KEPT`, and the box is left half-applied. Suggested fix: `set -E`, or set `failed=1` in `cleanup` whenever `rc` is nonzero.
3. **Early-failure revert leaves the drop-in loaded in networkd** (`step-11-revert.sh:56`, the `NETPLAN-UNCHANGED` branch). The revert removes the drop-in file but only runs `netplan apply` when the yaml differs. If the failure came before the yaml edit, networkd still holds `Promiscuous=yes` and `ARP=no` in memory. A carrier bounce on the SPAN port would re-apply them. Suggested fix: run `networkctl reload` in that branch.
4. **A quiet SPAN rolls back the whole step** (`:913-914`). `STOP-xdp-no-traffic` triggers `REVERTING`, which undoes promisc, netplan and tuning. That is by design, but the md should say so in the Paste section.
5. **Doc claims about revert are unverified.** The md says the revert restores `eno2np1` and "runs `netplan apply` only in that case". It does not say whether `eno2np1` returns to admin-up once `always-down` is gone. Say so, or check after the run.
6. **`sudo -v` as the first paste line** runs on rock-box, which needs no sudo. The sudo prompt that matters is the remote one under `ssh -t`. This is harmless, but the rule's rationale does not apply here.
7. **"No GRUB password yet" in Known gaps** (`os-handoff.md:118`) is now stale, since 1.4.1 is PASS per batch 10 (`docs/cis-fix/batch-10.md:107`). Fix it later in a docs commit. It is not a gate.
