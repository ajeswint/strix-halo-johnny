## B3. Coverage is the age of whatever `run-*.bin` files are still on disk

`docs/tool-install/module1-slice2b-boot-unit.md:646-666`. `base_date` is parsed at `:604-605` and used for the journal window only (`:695`).

File names match the reader. `open_next_file` uses `run-` + `%Y%m%dT%H%M%SZ` + `.bin`, and `run-<stamp>-NN.bin` on a same-second collision (`johnny-m1s2b-reader.py:38-39`, `:404-411`). The paste's `${fn#run-}` / `${ts%.bin}` / `${ts%-*}` / `${ts:0:4}`…`${ts:13:2}` split produced `2026-11-07 20:00:00 UTC` for both `run-20261107T200000Z.bin` and `run-20261107T200000Z-01.bin`. A deleted hour (`gap_secs=7200`) stopped. Gap `3700` passed and `3701` stopped (`-gt 3700` at `:680`). That part of the parser is right.

The set it measures is every retained file, including files opened before Paste B. `keep=200` and `file_max_seconds=3600` (`johnny-m1s2b-reader.service:12`) retain about 8.3 days. Replay: baseline `DATE-UTC` two days before the run, hourly files spanning about ten days, zero drop deltas, exit 0, `COVERAGE secs=863900`, `WEEK-DONE`. Count was 240. The script never requires `>= 168`.

So `M1S2B-NORC-WEEK-DONE` is not "seven days since apply". It is "the directory's oldest filename and newest mtime are at least 604800 s apart". Run early, and pre-apply files satisfy it. A gap older than the baseline can also false-fail the week.

Required fix: keep only files whose parsed start is at or after the baseline `DATE-UTC`. Require that set's span (`newest mtime - oldest post-baseline start`) `>= 604800`. Require the newest mtime within 3700 s of now, so a reader that stopped rotating cannot pass on stale mtimes. Keep the 3700 s gap test on that filtered set.

Line 704 says the paste also requires `count >= 168`, `du`/`df` within bounds, `NRestarts=0`, and `Result=success`. The script does not. `du`/`df` are printed (`:693-694`) and not compared. See B4 for the restart counters.

It is not the rate of the Johnny service:

- Min-size 1 Gbps is about 1.488e6 pps, essentially the bench number, before the cgroup cut.

The runbook's residual-risk list (`:478-484`) already names reader backlog, a single-queue flood, reboot, mirror oversubscription, and NIC drops. Keep that. Required wording: call 1.48e6 a Rock Box userspace loop on a 9900X, and state the unit caps and the single reader next to it. Do not leave it as "the reader's measured drain" beside the line-rate paragraph.

A restart does not skip ring records that are still between consumer and producer. The runbook's 4 MiB / `rb_full` caveat (`boot-unit.md:474`) is the right limit. Session line 44 says those records are drained "without loss" and omits that caveat. Use the runbook sentence.

`m2_cfg` is read once at process start (`johnny-m1s2b-reader.py:509`) and stored on the writer. Paste B's reader restart after `apply-cfg` is required for new file headers.
