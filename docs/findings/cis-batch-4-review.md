Script: `tests/cis-batch4/blocked-module-deps.py`.

## Verdict: APPROVE WITH CHANGES

The plan is sound and the central safety claims hold. Specifically:
- **No initrd rebuild is needed.** dracut-ng 110 copies `/etc/modprobe.d/*.conf` into the image only in hostonly mode.
- **The 73 blocked modules are safe.** Not one non-blocked module depends on any of them, apart from the dependents of the protocol, FireWire, USB-storage, 9p and cluster families themselves (all unneeded).
- **The apport mechanism is exactly as drafted.**
- **The `limits.d` ordering works.**
- **The sysctl drop-ins sort after the vendor files**, and none of the values can drop a frame that AF_PACKET, XDP or AF_XDP sees.

I found **no High finding and nothing that blocks Group P** (P1 to P3 are read-only; P4's only sudo actions are `lsinitrd`, `sha256sum` and a 42 MB `cp -a` into `/boot`, which cannot change what boots). There is one Medium (F1: the reboot gate does not pin the kernel, on a box with no fallback kernel and unattended security updates) and a set of Low and Info items: one wrong kernel-behaviour statement (F3), one wrong reading of kmod dry-run output (F2), a count the draft cannot reproduce (F4), gaps in the Q2 options (F5), and tidy-ups. None changes a command that AJ runs in Groups A to C except F6 (one extra read-only pre-check) and F8 (a tighter grep).
